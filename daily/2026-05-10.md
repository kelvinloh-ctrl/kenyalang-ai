### 1.4 DeepSeek V4 Flash 被塞进 MacBook Pro · ds4 推理引擎开源
- **来源**：[36kr AI (字母AI)](https://36kr.com/p/3803167337783561)
- **摘要**：Redis 原作者 antirez 在 GitHub 开源了一个叫 ds4 的项目 · 是为 DeepSeek V4 Flash 专门写的推理引擎 · 几千行 C 代码让 284B 参数（每次激活 13B）的模型跑在 128G 内存的 MacBook Pro 上。原本 FP16 需要两张 A100 80GB + 512GB DDR5 + 4TB NVMe（总成本 ~50 万人民币），现在 3 万块的 Mac 就能跑 · 支持 100 万 token 上下文。YC CEO Garry Tan 在 X 转了，说「正在下载」。
- **含义**：本地 agent 的 token 成本曲线被砸到 0 · 「重度 agent 用户一个月小几万 token 账单」这种叙事在 hardware 端被绕过。Kelvin 现在的 Mac fetcher 这条路径未来可以进一步把 LLM 也本地化。
- **行动**：等 ds4 出更稳的 build · 在 128G Mac 上做一次本地 coding agent 试跑 · 对比 Claude API 月成本。

### 1.5 图灵奖得主 Sutton 新作：用 1967 年 NLMS 公式破「流式 RL」壁垒
- **来源**：[36kr AI (机器之心)](https://36kr.com/p/3803073505369865)
- **摘要**：阿尔伯塔大学 Mahmood 团队 2024 年那篇「流式深度强化学习终于跑通了」（StreamX 系列）只是勉强越过流式壁垒。同组成员 + Openmind 研究院的合作者（含 Sutton）在新论文 Intentional Updates for Streaming Reinforcement Learning（arXiv:2604.19033v1）里换思路：不指定参数移动多少 · 而直接指定函数输出该改变多少 · 灵感来自 1967 年日本学者 Nagumo & Noda 的 NLMS 算法。
- **含义**：RL 在 agent 里一直是「批量训练才稳」 · 真正的 online learning 一直跑不通。这个方向打通后 · agent 在线自我改进的工程门槛会降一档。

### 1.6 InfoQ：Agent 时代需要怎样的分布式基础设施
- **来源**：[36kr AI (极客邦科技InfoQ)](https://36kr.com/p/3802850619809288)
- **摘要**：文章论点是 · 自 OpenClaw 现象级爆火后 Agent 已破圈进入实际场景 · 但 Agent 的「执行逻辑由大模型驱动 · 完全非确定性」与现有面向云原生确定性应用的基础设施根本不匹配。Agent 每次请求资源消耗差异极大（简单请求 vs 多轮工具调用 + 子 agent）· 容器微服务时代「凭经验给每个实例配相同资源」的做法在 Agent 时代会直接失效。
- **含义**：K8s + 微服务 + 镜像这套云原生范式在 Agent 时代要被改写 · 接下来是「agent-native infra」赛道（路由 / 资源弹性 / 可观测）的窗口期。
